# Skill: React + Tailwind app (coder agents)
Stack (fixed, already scaffolded): Vite + React 19 + TypeScript (strict) + Tailwind CSS v4. No other libraries, no router (switch views with React state), no backend.
- Persist data in localStorage; seed it from src/data/seed.json on first load (`import seed from './data/seed.json'`).
- src/main.tsx renders the default export of src/App.tsx inside the language provider, imports src/index.css (Tailwind + design tokens) and renders a floating EN/MN switch only as a fallback: place `<LanguageToggle />` (from the scaffold's i18n) in the header and on the login screen as the ui-design skill describes. Never create or edit src/main.tsx, src/index.css, src/theme.css or src/i18n.tsx.
- Every user-visible string goes through the scaffold's translator: `import { useT } from '../i18n'` (path relative to your file), `const t = useT()`, then `t('Add car')`. Pass a plain string literal in English (it is the translation key); put values in placeholders: `t('{count} cars found', { count })`, `t('Total: {amount}', { amount: formatMoney(total) })`. Never build sentences by concatenating translated pieces. Choice values stored in data (status, fuel type, transmission, location type, role, ...) are shown through one shared label helper per field that returns t('<English label>') for each value, and every component (cards, badges, tables, forms, filters) uses that helper, so no raw value ever reaches the screen untranslated. Pure modules in src/lib return data and codes, not UI text. Dates, emails and test ids are never translated; money is localized only through useMoney().
- Relative imports without file extensions. Match planned export signatures exactly.
- Put the ui_contract data-testid values on the matching elements.
- Style with Tailwind utilities following the design style guide; responsive grid; accessible labels on inputs.
- Never let undefined, null, NaN or empty separators reach the screen: hide a spec, chip or badge whose value is missing, build joined text by filtering out empty parts, and give number fields safe defaults when reading stored data.
- Every <img> from data has an onError fallback (a neutral bg-surface placeholder showing the item's name), because seed and user-entered image URLs can be dead.
- No embedded maps, iframes or third-party widgets: the app must work offline from the network except for images.
- Statuses (booking: Pending, Confirmed, Completed, Cancelled; car: Available, Unavailable) are always shown with the scaffold's `<StatusBadge status={...} />` from '../status' (it carries test id "status-badge", translates the label and picks the colour). Never hand-write a status pill.
- Icons come from the scaffold only: `import { Icon } from '../icons'` with names seats, bags, transmission, mileage, fuel, electric, location, calendar, info, check, star, map, chevron, search, heart, account. No other icon sets, no emoji in place of these.
- Place and address text from the data (city, address, pickup location, pickup instructions, rules) is displayed as `t(value)`: the translator translates the seeded ones into Mongolian, and text an owner typed shows as typed.
- Date + time: store bookings as `pickupDate` / `pickupTime` / `returnDate` / `returnTime` ("YYYY-MM-DD" and "HH:MM" strings). Show them as "2026-12-10 10:00" in English and "2026.12.10 10:00" in Mongolian, everywhere a booking appears (checkout summary, bookings, owner requests, confirmation). Days for pricing come from the dates only.
- Every amount shown on screen goes through the scaffold: `import { useMoney } from '../i18n'`, `const money = useMoney()`, `money(total)` gives "$280.00" in English and tugrik ("₮1,008,000") in Mongolian. Prices are stored in USD. Every money input (max daily rate filter and its slider, daily rate, cleaning fee) uses the scaffold's `useCurrency()`: show `cur.code` in the label or suffix (USD, or ₮ in Mongolian), display `cur.fromUsd(valueUsd)`, store `cur.toUsd(typed)`, use `step={cur.step}`; filter state stays in USD, so switching language converts what the user sees, never the data; pure src/lib functions return numbers, never formatted strings; never format money yourself with toFixed or Intl. Dates are YYYY-MM-DD; rental days = end - start in whole days.
- Shared state lives in App.tsx (or a store module) so a change in one role's view shows in the other role's view immediately.
- Role-based apps open on a lightweight login screen: exactly one quick-login card per role, never one per seeded user (avatar, name, role) with a "Log in as <name>" button; no passwords. The owner card is the seeded owner whose cars the demo uses; the renter card is the renter with no seeded bookings. Other seeded users stay in the data (they own other cars and made the seeded bookings) but get no card. After login the user sees their role's portal; the header shows the signed-in user and a "Log out" button that returns to the login screen. Persist the signed-in user id in localStorage.
- No email/password login and no sign-up form (unless the brief explicitly asks for accounts): a quick-login click takes the user straight to their role's portal.
- Every header menu item and link works from any screen: choosing it closes any open form, dialog or detail view and shows the chosen view, even when that view is already the current one (reset the view state rather than relying on a change).
- React 19 has no global JSX namespace: never write `JSX.Element` return types; omit the return type or use `React.ReactNode` (import type { ReactNode } from 'react').
- Text that a user reads as one phrase (e.g. car name and year "Kia Sportage 2023") is one string or has a literal space between its parts, never two adjacent elements with no text between them.
