# Skill: Playwright acceptance tests
- Two files written by two agents in parallel: e2e/acceptance.spec.ts (one test per test requirement, titled '<id>: <title>', plus 'QA: no broken values') and e2e/features.spec.ts (per-feature, I18N and pagination tests). Each agent writes only its own file.
- Creation tests fill only the fields the test requirement or brief names (e.g. TR-1: make, model, year, daily rate, location) and leave every other field at its default, exactly as a judge would; the listing must still save.
- Then one short test per spec feature that no test requirement already exercises, titled '<feature id>: <feature name>' (e.g. 'F-6: Earnings tracker'): reach the feature as a user would and check its main action works and its result is visible.
- Tests run in English (the default language); never click the language switch except in a test that is explicitly about languages.
- Always add one test titled 'QA: no broken values': for each role visit every main view (catalog, details, bookings, dashboard) and assert `await expect(page.locator('body')).not.toContainText(/undefined|NaN|null|\[object Object\]/)`.
- Always add one test titled 'I18N: Mongolian UI': for each role, log in, click getByTestId('lang-mn').first(), visit every main view, and assert that no visible element's exact text is an English choice value or status from the seed/spec (e.g. for cars: Automatic, Manual, Electric, Gasoline, Hybrid, Sedan, SUV, Pending, Confirmed, Owner, Renter). Use `await expect(page.getByText('Automatic', { exact: true })).toHaveCount(0)` per word, and check the logout button shows Mongolian text and prices show tugrik: `await expect(page.getByText(/₮/).first()).toBeVisible()`; also type a tugrik amount into the max daily rate filter (e.g. 324000 for $90) and check only cars at or under that price remain. All other tests stay in English, where prices read like $280.00. When a test does, use getByTestId('lang-mn') / ('lang-en') with .first(), since the header and fallback switch share those ids. `import { test, expect } from '@playwright/test'`.
- Every test starts with `await page.goto('/')` in a fresh browser context: localStorage is empty and seed data loads.
- The renter quick-login account starts with no bookings (seeded bookings belong to other renters), so tests that need a renter booking create it through the UI first, and one feature test checks the empty 'My bookings' state.
- Check the seed data before writing each test. If a test needs a state the seed does not contain (e.g. a Pending booking when the seed only has confirmed ones), create that state through the UI in the same test first (e.g. book as the renter, then switch to the owner).
- Log out the way a user would: click getByTestId('account-menu-btn'), then getByTestId('logout-btn'). Header sections may be dropdowns: open the menu button first, then click the item.
- Switch roles the way a user would: log in through the login screen (e.g. getByTestId('login-as-owner')), and log out before logging in as the other role. "Log into the Owner view" in a test requirement means exactly this.
- Locate elements with page.getByTestId(...) from the ui_contract; narrow with .filter({ hasText }) using case-insensitive regexes like /pending/i.
- Never locate an element by the state you are about to change: after clicking Approve, a row filtered by /pending/i no longer exists. Locate rows by stable identifying text (e.g. the car name), act, then assert the new status on that same stable locator.
- The catalog is paginated (6 per page): count matches with the results counter or by applying a filter, not by counting car-card on an unfiltered page; a just-created listing is on page 1. Add one test titled '<feature id>: Pagination' that moves to page 2 and back when there are more than 6 cars.
- Playwright cannot fill <input type="range">; price limits are set through the number input bound to the slider (it carries the filter test id). Fill date inputs with 'YYYY-MM-DD' strings computed from today's date by a small helper at the top of the file (e.g. `day(7)` = today + 7 days), never hard-coded calendar dates and never a pinned or mocked clock: the run may happen on any date, and past dates are rejected by the app. Time selects already default to 10:00, so tests may leave them; one feature test changes the pickup and return times and checks they appear in the booking. Use web-first assertions: toBeVisible, toHaveCount, toContainText.
- Reading a failure: the page snapshot shows what was really on screen. "waiting for getByTestId(x)" with x absent from the snapshot means either the app never rendered x or the test never created the state that shows it.
- Assert text, values and statuses, never icons or emoji (decorative icons are aria-hidden and may change).
